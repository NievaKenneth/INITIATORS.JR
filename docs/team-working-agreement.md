HOPE, Inc. ERP — Team Working Agreement
1. Purpose
This document establishes the working agreement, responsibilities, and Definition of Done for the HOPE, Inc. ERP project team.

2. Team Communication
Team members should communicate project updates clearly.
Members should report problems or blockers as soon as possible.
Questions about assigned tasks should be raised early.
Important project decisions should be documented.

3. Task Responsibilities
Each team member should work on assigned tasks.
Members should keep task progress updated.
Members should inform the team about delays.
Team members should coordinate when tasks depend on one another.
Members should provide assistance when reasonably needed.

4. GitHub Workflow
Each task should have a corresponding GitHub issue.
Each task should use its own working branch.
Changes should be submitted through pull requests.
Pull requests should reference their related issues.
Team members should review submitted changes.
Changes should follow the repository's branch protection requirements.

5. Collaboration and Respect
Respect the ideas and contributions of other members.
Give constructive feedback.
Communicate disagreements professionally.
Be accountable for assigned responsibilities.
Work together to resolve project problems.

6. Definition of Done
A task is considered Done when:

The task requirements have been completed.
All acceptance criteria have been checked.
Changes have been committed to the correct branch.
A pull request has been created and linked to its issue.
Required reviews and approvals have been completed.
Requested corrections have been addressed.
The pull request has been merged into main.
Relevant documentation has been updated when necessary.

7. Team Role Guide
Scrum Master
Coordinates sprint activities.
Maintains the sprint board.
Tracks progress and impediments.
Helps the team follow the agreed workflow.
Documents sprint reviews and retrospectives.

Developer
Implements assigned application features.
Follows project requirements.
Creates branches and pull requests.
Addresses review feedback.

Database Administrator
Maintains database structure and relationships.
Handles database scripts and migrations.
Supports data integrity and database documentation.

Tester
Prepares and performs test cases.
Checks features against acceptance criteria.
Reports defects and verifies fixes.

UI/UX Designer
Prepares interface designs and wireframes.
Provides design guidance.
Reviews interface consistency and usability.
