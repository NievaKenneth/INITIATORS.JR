HOPE ERP Design System

A practical, reusable visual language for HOPE Inc. business software: confident Forest Green, warm Ivory surfaces, restrained Gold accents, and clear, accessible workflows.

Approved direction: Corporate Foundation for all four sprints Version 1.0

01 · Foundations

Color usage rules

  • Use Dark Sidebar only for the persistent navigation shell; use white or Ivory for working surfaces.
  • Use Forest Green for primary buttons, active links, and key brand moments. Secondary Green supports hover and selected emphasis.
  • Use Gold sparingly for small highlights, focus/error cues, and accents—not large backgrounds or small text on white.
  • Use Sage for supportive fills such as active chips, selected rows, or subtle callouts; pair with dark text.
  • Use Main Text on White or Ivory for body copy. Use Border for quiet separators, not as the only indicator of meaning.
  • Do not introduce module-specific color palettes. Status meaning must also be conveyed with text or an icon.

Typography

Use Inter throughout. Load Inter in the host application when available; fall back to Segoe UI, then Arial, then sans-serif. Keep headings sentence case and reserve uppercase tracking for short labels.

03 · Application shell

Sidebar, header & page layout

Use a stable shell so users can move between ERP modules without relearning navigation. The sidebar is the dark anchor; the header and content surfaces stay light and uncluttered.

Desktop shell
Persistent 252px Dark Sidebar; flexible main column. At tablet widths the sidebar may reduce to approximately 218px.
Sidebar content
HOPE identity, module navigation, and role-aware links. Use the same navigation vocabulary across all six modules.
Header
White surface, 68px minimum height, breadcrumb or page context, then compact account and notification actions.
Page canvas
Ivory background. Center content within a 1120px maximum width; use 40px desktop padding and reduce at smaller breakpoints.
Content hierarchy
Page title and primary action first, supporting metadata next, then cards, forms, or tables grouped by task.
Roles
Superadmin, Admin, and User share the design system. Gate destinations and actions by permission; do not encode role meaning with a color change.
Responsive navigation
Below 720px, convert the sidebar module links to a horizontally scrollable top navigation; keep targets reachable and labels visible.
Responsive tables
Contain wide tables in an overflow-x:auto region. Keep headers, row labels, and controls usable without clipping.

Module and role consistency

Reuse the same controls, status vocabulary, page hierarchy, and table behavior in Customers, Products, Human Resources, Sales, Reports, and User Management. Superadmin and Admin may see different actions than User, but shared components should not change visual language. Hide or disable unavailable actions according to product policy; explain disabled actions when the reason is not obvious.

04 · Interaction & accessibility

States, accessibility & developer handoff

Provide predictable feedback for pointer, keyboard, validation, and assistive-technology users. Preserve readable contrast and never communicate a state by color alone.

StateTreatmentImplementation note
HoverSubtle green or Sage surface shift; clear pointer affordance.Use for interactive elements only; do not make hover the sole feedback.
FocusVisible 2px Secondary Green outline with 2px offset and soft ring.Use :focus-visible; preserve keyboard focus and do not remove browser outlines without a replacement.
Selected / currentGreen surface or Sage fill plus a distinct edge or selected indicator.Expose with aria-current, aria-selected, or native control state as appropriate.
DisabledBorder token and muted text on a light neutral fill; no hover emphasis.Use native disabled where applicable; retain legibility and explain unavailable actions when needed.
ErrorStrong Forest Green outline with a Gold accent and visible, explicit error message.Set aria-invalid and connect help/error text with aria-describedby. Do not rely on color alone.
Active / pending / inactiveSage, warm pale Gold, and Ivory chip fills with explicit text labels.Use the shared status labels and color tokens consistently across modules.

Accessibility checklist

  • Meet WCAG AA contrast for normal text (4.5:1) and large text (3:1); validate real rendered color pairs.
  • Use semantic headings, landmarks, labels, table headers, and native controls.
  • Keep all actions keyboard-operable with a clearly visible focus indicator.
  • Provide descriptive accessible names for icon-only buttons and decorative-image alternatives.
  • Pair status and validation colors with visible labels or messages.
  • Respect reduced-motion preferences and maintain a usable zoom/reflow layout.

Developer handoff

  • Map the CSS custom properties at the top of this file to shared theme tokens.
  • Implement buttons, fields, chips, cards, tables, and navigation as shared components.
  • Use the supplied type scale, spacing increments, radii, and interaction states as defaults.
  • Load Inter through the approved application font pipeline; this reference has no external dependencies.
  • Do not treat this reference as a dashboard or production page implementation.
  • Test component contrast and behavior in each role and responsive breakpoint before release.
Design guardrail: Forest Green, Ivory, and the Dark Sidebar remain the defining visual direction. Gold is an accent, not a competing primary color. Keep all future modules inside this shared system.
